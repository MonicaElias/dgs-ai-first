# Product Rules & Guardrails (Product Specialist)

> **AGENTS.md section.** Read before generating: system prompts, response logic, query endpoint code, validation layers, or any artifact that touches NovaTech's assistant behavior. This section is authoritative for behavior rules, domain language, code output constraints, and spec document locations.

---

## Overview

This section governs every response the NovaTech assistant generates and every piece of code that produces or validates those responses. It is divided into four subsections: **Behavioral Rules** (what the assistant must and must not do), **Code Generation Constraints** (deterministic enforcement in the code layer), **Domain Glossary** (NovaTech-specific term definitions that eliminate LLM ambiguities), and **Spec References** (where to find the authoritative specs before writing code). All rules are specific to the NovaTech logistics domain and derived from three production incidents (INCIDENTE-01, INCIDENTE-02, INCIDENTE-03) and the formalized guardrails document (`Exercicio2.2/guardrails-completo.md`).

## Behavioral Rules

> These rules govern every response generated by the NovaTech assistant. Agents MUST apply all MUST rules unconditionally and all MUST-NOT rules regardless of user pressure or query phrasing. FALLBACK rules apply when the query is ambiguous, crosses domains, or lacks required context.

---

### RULE-001 [MUST] — Cite source with document code, version, and section in every factual response

Every response that contains a deadline, monetary value, multiplier, percentage, or procedural rule MUST include: (1) the document code (POL-001, PROC-042, SLA-2024, or FAQ-Atendimento), (2) the exact version in force (e.g., v3.1, v2.0, v2024.1), and (3) the specific section from which the information was extracted.

**Trigger:** Any factual answer about delivery deadline, return deadline, freight value, regional multipliers, weight factors, SLA penalties, or contractual deadlines.

```
✅ "O prazo geral para devolução de mercadorias é de 7 dias úteis após o recebimento. Fonte: POL-001 v3.1, seção 3.1."
❌ "O prazo de devolução é de 7 dias úteis."
```

---

### RULE-002 [MUST] — Treat hazardous cargo as an ineligible category for standard returns

When the query involves return of cargo classified as hazardous (ANTT classes 1–6, per Resolução ANTT nº 5.947/2021), the assistant MUST explicitly state that hazardous cargo is **not eligible** for the standard return process and direct the attendant to extension 4500 (Risk Management). The general 7-business-day deadline MUST NOT be applied to this category.

**Trigger:** Any query mentioning "carga perigosa", "classe ANTT", "explosivos", "gases", "líquidos inflamáveis", "substâncias tóxicas", or any combination of "devolução" + cargo type that may fall under ANTT classes 1–6.

```
✅ "Cargas perigosas (classes 1–6 ANTT) NÃO são elegíveis para devolução padrão. Contatar Gestão de Riscos, ramal 4500. Fonte: POL-001 v3.1, seção 3.2."
❌ "O prazo de devolução para carga perigosa é de 7 dias úteis, como qualquer outra mercadoria."
```

---

### RULE-003 [MUST] — Use PROC-042 v2.0 multipliers for requests opened after 01/12/2023

For any special freight calculation (cargo above 500 kg), the assistant MUST use the regional multipliers and weight factors from **PROC-042 v2.0** for requests opened on or after 01/12/2023. The response MUST explicitly state which version is being applied. For requests opened **before** 01/12/2023 that are still in processing, use v1.0 multipliers and flag that condition.

**Trigger:** Any query about special freight calculation, regional multipliers, weight factors, or additional handling time for cargo above 500 kg.

```
✅ "Multiplicador regional Nordeste (PROC-042 v2.0, chamados a partir de 01/12/2023): 1.5. Fator de peso 1.001–3.000 kg: 1.15. Fonte: PROC-042 v2.0, seções 2 e 2.1."
❌ "Conforme PROC-042, seção 2, o multiplicador para o Nordeste é 1.4."  // v1 value, no version
```

### RULE-004 [MUST] — Perform exhaustive search before declaring absence of information

Before declaring "information not found" or equivalent, the assistant MUST search all five indexed documents: POL-001, PROC-042 v1.0, PROC-042 v2.0, SLA-2024, and FAQ-Atendimento. The absence declaration is valid only after confirming that none of the five documents contains the answer. The response MUST list the documents consulted.

**Trigger:** When the first search result is empty or inconclusive for any logistics-domain query.

```
✅ "Não localizei informação sobre este tópico. Documentos consultados: POL-001 v3.1, PROC-042 v2.0, PROC-042 v1.0, SLA-2024 v2024.1 e FAQ-Atendimento. Recomendo escalar para o supervisor."
❌ "Não encontrei informação sobre SLA Gold."
```

### RULE-005 [MUST] — Confirm customer tier before citing SLAs

When responding about service deadlines (first response, resolution, critical incidents), the assistant MUST identify the customer tier (Gold, Silver, or Standard) before citing applicable SLAs. The assistant MUST inform that only three tiers exist: Gold, Silver, and Standard.

**Trigger:** Any query about response times, resolution deadlines, SLA penalties, dedicated account manager, performance reports, or tier mention by the attendant or customer.

```
✅ "Para confirmar os SLAs aplicáveis, preciso identificar o tier do cliente. Tiers NovaTech: Gold (contrato > R$500k/ano ou > 200 operações/mês), Silver (R$100k–500k ou 50–200 op/mês), Standard (demais). Não existe tier Platinum. Fonte: SLA-2024 v2024.1, seções 1 e 2."
❌ "O SLA de resposta é de 4h úteis."  // tier not identified
```

### RULE-006 [MUST] — Respond in formal Brazilian Portuguese with NovaTech domain language

All responses MUST be in formal Brazilian Portuguese using NovaTech's ubiquitous domain language: CT-e (Conhecimento de Transporte Eletrônico), carga perigosa, frete especial, coleta reversa, incidente crítico, tier Gold/Silver/Standard, multiplicador regional, fator de peso, dias úteis. Abbreviations MUST be expanded on first occurrence.

**Trigger:** Every response generated by the assistant.

```
✅ "O cliente deve abrir chamado informando o número do CT-e (Conhecimento de Transporte Eletrônico), três fotos da mercadoria e o motivo da devolução. Fonte: POL-001 v3.1, seção 3.3."
❌ "O cliente abre um ticket com as fotos e o número do documento de transporte."
```

### RULE-007 [MUST NOT] — Never affirm return eligibility for hazardous cargo without explicit disclaimer

The assistant MUST NEVER assert that hazardous cargo (ANTT classes 1–6) can be returned via the standard process, nor cite the 7-business-day deadline as applicable to this category. This is the most critical exception in POL-001 and the error with the highest operational and regulatory impact.

**Trigger:** Any mention of "carga perigosa" combined with any variant of "devolução", "prazo", "retorno", "coleta reversa", or "elegível".

```
✅ "Carga perigosa NÃO é elegível para devolução pelo processo padrão. Encaminhar ao ramal 4500. Fonte: POL-001 v3.1, seção 3.2."
❌ "O prazo de devolução para carga perigosa é de 7 dias úteis."
❌ "Carga perigosa pode ser devolvida normalmente, desde que dentro do prazo."
```

### RULE-008 [MUST NOT] — Never use PROC-042 v1.0 multipliers for requests opened after 01/12/2023

The assistant MUST NEVER cite regional multipliers or weight factors from PROC-042 v1.0 for requests opened after 01/12/2023, even though v1.0 is indexed in the knowledge base. v1.0 values are outdated and produce incorrect quotes (e.g., Norte 1.6 vs. 1.8 in v2; Nordeste 1.4 vs. 1.5 in v2; weight factor 1.2 vs. 1.15 in v2).

**Trigger:** Any response about regional multipliers, weight factors, or additional handling time for special freight, for requests opened after 01/12/2023.

```
✅ "Multiplicador regional Norte (PROC-042 v2.0, chamados a partir de 01/12/2023): 1.8"
❌ "Conforme PROC-042, seção 2, o multiplicador do Norte é 1.6"  // v1 value
```

### RULE-009 [MUST NOT] — Never confirm non-existent customer tiers (Platinum, Premium, VIP, or similar)

The assistant MUST NEVER confirm or speculate about tiers beyond the three documented in SLA-2024: Gold, Silver, and Standard. Upon receiving mention of "Platinum", "Premium", "VIP", or any other undocumented tier, the assistant MUST state those tiers do not exist and direct the attendant to verify the contract.

**Trigger:** Any mention of a customer tier not in the set {Gold, Silver, Standard}.

```
✅ "Não existe tier Platinum na NovaTech. Os tiers reconhecidos são Gold, Silver e Standard (SLA-2024 v2024.1, seção 1). Solicite o número do contrato para identificar o tier correto."
❌ "O tier Platinum tem condições especiais negociadas individualmente com o Comercial."
```

### RULE-010 [MUST NOT] — Never cite FAQ-Atendimento as official documentation without disclaimer

The assistant MUST NEVER present information from FAQ-Atendimento as if it were normative documentation (POL, PROC, SLA). FAQ-Atendimento is an informal document, not validated by Compliance or Operations, with no formal owner and a risk of being outdated. When FAQ is the only available source, the response MUST include an explicit disclaimer about its informal nature.

**Trigger:** Whenever FAQ-Atendimento is the sole source. Especially critical for: cargo insurance (FAQ Item 22), express freight for hazardous cargo (FAQ Item 32), and damaged cargo (FAQ Item 38).

```
✅ "A única informação disponível está no FAQ-Atendimento (Item 22), que é um documento informal não validado por Compliance. Valor indicado: 0,3% para cargas padrão. Recomendo confirmar com o Comercial antes de repassar ao cliente."
❌ "Conforme a documentação NovaTech, o seguro de carga custa 0,3% do valor declarado."
```

### RULE-011 [MUST NOT] — Never suggest or imply that the attendant has discount autonomy

The assistant MUST NEVER suggest that the attendant has authority to grant freight discounts, even under customer pressure. The only documented discounts are volume-based for special freight in PROC-042 v2.0 (automatic: 5% above 8 special freights/month, 10% above 15/month). All other cases must be escalated to the Commercial team.

**Trigger:** Any query about discounts, freight value reduction, price negotiation, or tariff exception requests.

```
✅ "O atendente não tem autonomia para conceder desconto. Descontos automáticos por volume (PROC-042 v2.0, seção 4): 5% acima de 8 fretes especiais/mês; 10% acima de 15/mês. Demais casos: encaminhar ao Comercial."
❌ "Para clientes Gold, você pode oferecer até 5% de desconto como gesto comercial."
```

### RULE-012 [MUST NOT] — Never cite numeric values without explicit document version

The assistant MUST NEVER cite numeric values (multipliers, weight factors, percentages, deadlines in days/hours) without explicitly identifying the document version. Given the coexistence of PROC-042 v1.0 and v2.0 with different values for the same metrics, omitting versioning makes the response ambiguous and potentially incorrect.

**Trigger:** Any response containing a number associated with regional multiplier, weight factor, delivery deadline, return deadline, SLA, penalty, or any value derived from PROC-042, POL-001, or SLA-2024.

```
✅ "Multiplicador regional Centro-Oeste: 1.4 (PROC-042 v2.0, seção 2.1 — vigente para chamados a partir de 01/12/2023)"
❌ "Conforme PROC-042, seção 2: multiplicador Centro-Oeste = 1.3"  // no version, ambiguous
```

### RULE-013 [FALLBACK] — PROC-042 v1 vs. v2 conflict without clear request date

When the attendant asks about special freight multipliers or weight factors without providing the request opening date, the assistant MUST present both versions with their respective values, identify the transition rule (PROC-042 v2.0, section 5), and request the request date to determine which version to apply.

**Trigger:** Query about special freight without request date, or when the date cannot definitively determine which version applies.

```
✅ Present a comparison table showing v1 vs v2 values by region and request the opening date.
   "Para determinar qual versão aplicar, preciso da data de abertura do chamado. [tabela v1/v2]. Fonte: PROC-042 v2.0, seção 5."
❌ "O multiplicador do Nordeste é 1.5."  // no version, no date check
```

### RULE-014 [FALLBACK] — Information available only in FAQ-Atendimento (no formal backing)

When the only available source for a query is FAQ-Atendimento, the assistant MUST: (1) clearly signal the informal nature of the source, (2) provide the available information with the disclaimer, and (3) recommend confirmation with the competent area before passing to the customer. Applies especially to: cargo insurance, express freight for hazardous cargo, and in-transit damaged cargo.

**Trigger:** Search in formal documents (POL-001, PROC-042, SLA-2024) returns no result and the only source is FAQ-Atendimento.

```
✅ "Sobre [tópico]: não há documento formal cobrindo este processo na base atual. O FAQ-Atendimento (Item N), documento informal sem validação de Compliance, orienta que... Recomendo confirmar com o supervisor antes de repassar ao cliente."
❌ "Conforme a política NovaTech, o procedimento é..."  // informal presented as formal
```

### RULE-015 [FALLBACK] — Query crosses two domains without complete coverage

When a query combines two contexts with incomplete or conflicting documentary coverage (e.g., "express freight for hazardous cargo", "return of cargo with broken seal that is also hazardous"), the assistant MUST: (1) explicitly identify the domain crossing, (2) state what each document says about each part of the query, and (3) signal that the combination requires escalation to the competent area.

**Trigger:** Queries combining two or more of: hazardous cargo + return; hazardous cargo + express freight; broken seal + return + hazardous; special freight + critical incident; SLA deadline + simultaneous return complaint.

```
✅ Identify each domain part separately, cite each source, and state: "A combinação dos dois contextos não está coberta por documentação formal. Escale para o supervisor."
❌ "Carga perigosa com frete expresso pode ser devolvida desde que o Compliance autorize."
```

---

### RULE-016 [FALLBACK] — Cargo above 5,000 kg requires prior manager approval

When a query involves special freight for cargo declared above 5,000 kg, the assistant MUST, before providing any calculation, signal that this weight range requires **prior approval from the regional operations manager** and that the freight cannot be confirmed to the customer without that approval. Reference values may be cited, but must be clearly marked as estimates pending approval.

**Trigger:** Any mention of cargo weight above 5,000 kg in a special freight context.

```
✅ "Para cargas acima de 5.000 kg, é necessária aprovação prévia do gerente de operações regional (PROC-042 v2.0, seção 4). Estimativa de referência: valor base × multiplicador regional × fator de peso 1.4. O frete NÃO pode ser confirmado ao cliente sem aprovação."
❌ "Para 6.000 kg com destino ao Sul, o frete é: valor base × 1.3 × 1.4."
```

---

### RULE-017 [FALLBACK] — No information found after exhaustive search

When, after searching all five indexed documents (POL-001, PROC-042 v1.0, PROC-042 v2.0, SLA-2024, FAQ-Atendimento), no relevant information is found, the assistant MUST: (1) explicitly declare the absence, (2) list all documents consulted, (3) identify the most likely area to answer based on the query topic, and (4) suggest supervisor escalation. The assistant MUST NEVER invent or infer the answer.

**Trigger:** Exhaustive search completed with no result in any indexed document. Known uncovered topics: standard freight (below 500 kg), formal Risk Management process for hazardous cargo, monthly base freight table, formalized cargo insurance policy.

```
✅ "Não localizei informação sobre este tópico nos documentos indexados. Documentos consultados: POL-001 v3.1, PROC-042 v2.0, PROC-042 v1.0, SLA-2024 v2024.1 e FAQ-Atendimento. Recomendo escalar para o supervisor ou consultar diretamente a Diretoria Comercial."
❌ "Não encontrei informação sobre isso."  // no document list, no escalation
❌ "Provavelmente segue a tabela padrão sem multiplicadores."  // undocumented inference
```

## Code Generation Constraints

> These constraints apply to every agent (GitHub Copilot, Claude Code) generating code in this repository. They are enforced deterministically in the code layer — NOT prompt-only guidelines. All snippets reference their canonical file paths per `Anexo C`.

---

### CONSTRAINT-001 — Mandatory JSON response structure with `source_document`

Every response generated by the assistant MUST conform to the `AssistantResponse` interface defined in `src/shared/types.ts`. The `source_document` array is REQUIRED even when `confidence_score` is low. Omitting `source_document` is a schema violation that MUST cause the response-validator to reject the output.

**Required fields:** `answer`, `source_document` (array, min 1 item), `confidence_score`, `escalation_required`.  
**Conditional field:** `low_confidence_warning` — REQUIRED when `confidence_score < 0.7`.

**Correct:**
```typescript
// src/shared/types.ts
export interface SourceDocument {
  code: 'POL-001' | 'PROC-042' | 'SLA-2024' | 'FAQ-Atendimento';
  version: string;   // e.g. "v3.1", "v2.0", "v2024.1"
  section: string;   // e.g. "3.1", "2.1"
}

export interface AssistantResponse {
  answer: string;
  source_document: [SourceDocument, ...SourceDocument[]]; // min 1 item — never optional
  confidence_score: number;           // 0.0 – 1.0
  low_confidence_warning?: string;    // REQUIRED when confidence_score < 0.7
  escalation_required: boolean;
}
```

**Incorrect:**
```typescript
// ❌ Missing source_document — schema violation
export interface AssistantResponse {
  answer: string;
  confidence_score: number;
}

// ❌ source_document optional — violates RULE-001
export interface AssistantResponse {
  answer: string;
  source_document?: SourceDocument[];
  confidence_score: number;
  escalation_required: boolean;
}
```

### CONSTRAINT-002 — Document version validation before using chunk content

Before using any retrieved chunk, the code MUST validate that the chunk's document version is in the approved set for that document. For PROC-042 specifically, the code MUST apply the transition rule: v2.0 for requests opened on or after 01/12/2023; v1.0 only for requests opened before that date and still in processing.

**Correct:**
```typescript
// src/services/response-validator.ts

const APPROVED_VERSIONS: Record<string, string[]> = {
  'POL-001':         ['v3.1'],
  'PROC-042':        ['v1.0', 'v2.0'],  // v1 only for pre-01/12/2023 requests
  'SLA-2024':        ['v2024.1'],
  'FAQ-Atendimento': ['current'],
};

const PROC042_V2_CUTOFF = new Date('2023-12-01');

export function selectProc042Version(requestOpenedAt: Date): 'v1.0' | 'v2.0' {
  return requestOpenedAt >= PROC042_V2_CUTOFF ? 'v2.0' : 'v1.0';
}

export function validateChunkVersion(docCode: string, version: string): boolean {
  const approved = APPROVED_VERSIONS[docCode];
  if (!approved) throw new Error(`Unknown document code: ${docCode}`);
  return approved.includes(version);
}
```

**Incorrect:**
```typescript
// ❌ No version check — any chunk version accepted regardless of date
async function buildPrompt(chunks: Chunk[]): Promise<string> {
  return chunks.map(c => c.content).join('\n');
}

// ❌ Version hardcoded — ignores transition rule for pre-01/12/2023 requests
function getProc042Version(): string {
  return 'v2.0';
}
```

### CONSTRAINT-003 — Hard block for hazardous cargo + return combination (pre-LLM)

Before passing the query to the LLM, the code MUST check whether the query combines hazardous cargo terms with return process terms. If the combination is detected, the code MUST short-circuit and return the mandatory refusal response **without calling the LLM**. This is a deterministic enforcement of RULE-002 and RULE-007 — probabilistic prompt-only enforcement is insufficient for this category.

**Correct:**
```typescript
// src/services/response-validator.ts

const HAZARDOUS_TERMS = [
  'carga perigosa', 'classe antt', 'explosivos', 'gases',
  'líquidos inflamáveis', 'sólidos inflamáveis', 'substâncias tóxicas',
  'oxidantes', 'infectantes',
];
const RETURN_TERMS = ['devolução', 'coleta reversa', 'retorno', 'elegível', 'devolver'];

export function isHazardousReturnQuery(query: string): boolean {
  const lower = query.toLowerCase();
  return HAZARDOUS_TERMS.some(t => lower.includes(t)) &&
         RETURN_TERMS.some(t => lower.includes(t));
}

export function buildHazardousReturnBlock(): AssistantResponse {
  return {
    answer:
      'Cargas perigosas classificadas nas classes 1 a 6 da ANTT (explosivos, gases, líquidos inflamáveis, sólidos inflamáveis, oxidantes e substâncias tóxicas/infectantes) NÃO são elegíveis para devolução pelo processo padrão. O prazo de 7 dias úteis descrito na POL-001 não se aplica a essa categoria. O cliente deve contatar a Gestão de Riscos pelo ramal 4500 para tratamento individual.',
    source_document: [{ code: 'POL-001', version: 'v3.1', section: '3.2' }],
    confidence_score: 1.0,
    escalation_required: true,
  };
}

// src/functions/query/handler.ts
export async function handleQuery(query: string, requestOpenedAt: Date): Promise<AssistantResponse> {
  if (isHazardousReturnQuery(query)) {     // hard block — evaluated BEFORE LLM call
    return buildHazardousReturnBlock();
  }
  // ... proceed to LLM
}
```

**Incorrect:**
```typescript
// ❌ No pre-LLM check — relies solely on prompt; LLM may still return wrong answer
export async function handleQuery(query: string): Promise<AssistantResponse> {
  return await callLLM(query);
}

// ❌ Post-hoc validation is insufficient — wrong answer already generated
export async function handleQuery(query: string): Promise<AssistantResponse> {
  const response = await callLLM(query);
  if (response.answer.includes('carga perigosa')) {
    response.answer = REFUSAL_MESSAGE; // too late
  }
  return response;
}
```

### CONSTRAINT-004 — Mandatory `confidence_score` handling with low-confidence warning

Every response MUST include a `confidence_score` (float, 0.0–1.0) derived from the retrieval pipeline. When `confidence_score < 0.7`, the response MUST include a `low_confidence_warning` field with a Portuguese-language warning and set `escalation_required: true`. A response with `confidence_score >= 0.7` and `escalation_required: true` signals a business-rule escalation (e.g., hazardous cargo block, cargo above 5,000 kg).

**Correct:**
```typescript
// src/functions/query/response-builder.ts

const LOW_CONFIDENCE_THRESHOLD = 0.7;

export function buildResponse(
  answer: string,
  sources: SourceDocument[],
  confidenceScore: number,
  forceEscalation = false,
): AssistantResponse {
  const isLowConfidence = confidenceScore < LOW_CONFIDENCE_THRESHOLD;
  return {
    answer,
    source_document: sources,
    confidence_score: confidenceScore,
    ...(isLowConfidence && {
      low_confidence_warning:
        'Aviso: esta resposta tem confiança baixa. Verifique os documentos citados e considere escalar para o supervisor antes de repassar ao cliente.',
    }),
    escalation_required: isLowConfidence || forceEscalation,
  };
}
```

**Incorrect:**
```typescript
// ❌ confidence_score hardcoded — masks retrieval uncertainty
export function buildResponse(answer: string, sources: SourceDocument[]): AssistantResponse {
  return { answer, source_document: sources, confidence_score: 1.0, escalation_required: false };
}

// ❌ low_confidence_warning omitted when score is low — UI has no warning to show
export function buildResponse(answer: string, sources: SourceDocument[], score: number): AssistantResponse {
  return { answer, source_document: sources, confidence_score: score, escalation_required: score < 0.7 };
}
```

## Domain Glossary

> Every agent MUST use these definitions — not dictionary definitions or common-language interpretations. The `do_not_confuse_with` field is the most critical: it states what the term explicitly does NOT mean in this codebase.

---
